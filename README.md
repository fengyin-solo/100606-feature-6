# 机场地面保障作业管理平台

面向航班保障、机位分配、廊桥靠接、摆渡车调度、行李装卸、航油加注、除冰作业与延误处置的一体化机场地面保障作业工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `airport-ground-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 航班保障占用校验

机位与保障班组的占用校验集中在 `frontend/src/data/occupancy.ts`（独立于页面的占用账本），
占用账本 key 为 `airport-ground-ops:occupancy-ledger`，与业务数据分开持久化。规则：

- **占用时段**：以「计划到达」为起点的 60 分钟，区间左闭右开（相隔正好 60 分钟不算撞）。
- **校验入口**：登记（`createFlight`）与接收（动作「接收任务」）都按计划到达时段核机位号与
  保障班组；登记时撞车仍可入账进待办，接收时撞车直接拦截，任务留在「待接收」。
- **筛选路径**：值班员先按「计划到达 + 保障等级」筛选（航班页筛选栏），再对筛选结果逐条核
  冲突。冲突在**全量任务**上评估（冲突对方可能不在筛选子集内），只取筛选子集里的任务计数；
  报告里的 `conflictCount / standEvidenceCount / teamEvidenceCount` 三者恒等，筛出几条冲突
  就报几条，不会"筛十条报六条"。
- **双证据主次**：机位与班组在同一时段都被占时，两条证据同时成立并成对回写；以**机位冲突为
  主判定**（机位是现场硬约束），班组冲突并列展示（`kind=both, primary=stand`）。
- **让位次序（回填与新登记一致）**：按「计划到达」升序逐条落位（到场先到先得）；同一时刻
  保障等级高者优先（要客 > 重要 > 普通）；再相同则任务 id 小者优先。后落位的一方让位，让位
  任务不删除，冲突证据进占用待办。存量任务在应用启动时（`bootstrapOccupancy`）按同一次序
  回填，重复打开幂等。
- **待办回写**：每次评估都把冲突结果成对回写到停机位与保障班组的「占用待办」列；仅班组冲突
  时机位侧挂到「班组联动待办」虚拟汇总行，仅机位冲突时班组侧写「机位联动待办」，保证两侧
  条数一致。机位「当前航班/占用时段/机位状态」只由占用账本写，与航班任务是同一份；任务
  「保障完成」后释放占用，冲突随之消解的待办同步清除。
- **状态机**：待接收 → 保障中 → 保障完成，只许顺序推进不许跳步；「开始保障」只记录实际
  开工、不产生状态跳转。同一条任务重复接收只算一次占用（幂等返回）。
- 占用校验测试：`cd frontend && npm test`（esbuild 打包数据层到 `test/build-test/`，
  纯 Node 内存存储，不依赖浏览器）。
